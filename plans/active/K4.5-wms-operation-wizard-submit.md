# K4.5 — Декомпозировать submit orchestration WMS operation wizard

## Problem

Повторное измерение после K4.4 показывает, что `handleSubmit` в
[`WmsOperationWizardDialog.tsx`](../../apps/web/src/components/wms/WmsOperationWizardDialog.tsx:381)
имеет `cx 42` и 178 строк по границам checker. Обработчик объединяет выбор
endpoint, payload construction, response mapping, notifications and callbacks.

## Verified map

- [KNOWN] Единственный consumer submit handler — локальный `onSubmit={handleSubmit}`
  в [`WmsOperationWizardDialog.tsx`](../../apps/web/src/components/wms/WmsOperationWizardDialog.tsx:521).
- [KNOWN] Existing payload builder is
  [`buildOperationSubmitPayload`](../../apps/web/src/components/wms/operation-submit.ts:13)
  and must remain the source of request payload semantics.
- [KNOWN] Transfer requests use `POST /api/wms/transfers`; regular operations use
  `POST /api/wms/operations`.
- [KNOWN] Success invokes `onSuccess(json.data.id)` and `onClose()`; API and
  network errors use existing snackbar messages.
- [KNOWN] Existing test runner discovers colocated `*.test.ts` files; no new
  dependency is required.

## Scope

Вынести только submit request execution and response mapping into a neighboring
pure/testable module. Preserve operation-vs-transfer endpoint selection,
payload builder input, success/error/network notifications, `onSuccess`,
`onClose`, and `isSubmitting` lifecycle. Do not change API routes, permissions,
rate limiting, UI presentation, K6, or unrelated K4 candidates.

## Acceptance criteria

1. `handleSubmit` complexity becomes `<= 10` or any remaining orchestration
   boundary is explicitly documented in Result.
2. Focused tests cover transfer success, operation success, API error, and
   network error mapping.
3. Source, consumer, payload builder, and callbacks preserve existing contracts.
4. Targeted tests, full tests, lint, web TypeScript, and quality baseline pass.
5. This bounded stage is closed with its own Conventional Commit.

## Ponytail check

Rung 1 does not apply: the wizard must submit transfer and warehouse operation
requests. Rungs 2–4 confirm that existing `fetch`, payload builder, snackbar,
and React callbacks are sufficient; no dependency or generic request framework
is needed. Rung 6: minimum implementation is one neighboring submit helper with
explicit callbacks and focused tests.
