# K4.8 — Декомпозировать GET реестра оборудования EPS

## Problem

Восьмое измерение после K4.7 показало, что следующий проверенный business
candidate — [`GET()`](../../../apps/web/src/app/api/eps/equipment/route.ts:10) с
`cx 24` и 145 строками по границам quality checker. Handler одновременно
разбирает query-параметры, строит Prisma filter, загружает реестр и агрегаты,
собирает status counts и форматирует response.

Численно более высокие результаты для
[`WmsOperationWizardDialog`](../../../apps/web/src/components/wms/WmsOperationWizardDialog.tsx),
[`handleRequestSort()`](../../../apps/web/src/app/eps/history/page.tsx:84),
[`parseDateSafe()`](../../../apps/web/src/app/api/eps/equipment/[id]/route.ts:148) и
SRM/presentation boundaries остаются false-positive или presentation boundaries
и не входят в эту bounded stage.

## Verified map

- [KNOWN] Единственный route handler для scope —
  [`apps/web/src/app/api/eps/equipment/route.ts`](../../../apps/web/src/app/api/eps/equipment/route.ts).
- [KNOWN] GET response contract contains `success` and `data.items`, pagination,
  `statusCounts`; POST handler is in the same file and is out of scope.
- [KNOWN] Prisma types and `EquipmentStatus` are imported from `@ems/database`;
  no new dependency is required.
- [KNOWN] Authorization, rate limiting, Prisma includes/query shape, pagination,
  response mapping, permission semantics and error handling must remain unchanged.
- [KNOWN] Existing test runner discovers web tests only under
  `apps/web/src/lib/__tests__`; focused tests for a neighboring helper require
  explicit runner coverage or a supported test location.

## Scope

Вынести только pure query parsing/filter construction, status aggregation and
safe response mapping needed by GET. Preserve Prisma query shape, includes,
permission and rate-limit behavior, GET response contract, POST behavior, UI,
K6 and other K4 candidates.

One logical remediation stage: EPS equipment registry GET query/status
construction. Do not extract POST logic or change database semantics.
