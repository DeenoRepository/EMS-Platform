# O0 — Дорожная карта полного покрытия проекта и бизнес-логики тестами

## Problem

[`docs/quality/COVERAGE_BASELINE.md`](../../docs/quality/COVERAGE_BASELINE.md)
на 2026-09-01 фиксирует:

| Метрика | Факт | Порог |
|---|---:|---:|
| Line coverage среди загруженных файлов | 83.00 % | 70 % |
| File-level coverage (reach) | 55.41 % | 22 % |
| Component line coverage | 2.63 % | 1 % |
| Файлов с нулевым покрытием | 165 из 370 (44.6 %) | — |

Фактический замер поверхности кода (2026-09-01):

| Поверхность | Всего | Покрыто | Не покрыто |
|---|---:|---:|---:|
| API-роуты (`app/api/**/route.ts`) | 85 | 33 | **52** |
| Модули `apps/web/src/lib/**` | 34 | 23 | **11** |
| React-компоненты (`components/**`) | 160 | 13 | **147** |
| Страницы (`app/**/page.tsx`) | 27 | 0 | **27** |
| Пакет `@ems/auth` | 5 модулей | 4 | **1** (`audit.ts`) |
| Пакет `@ems/shared` | 5 модулей | 0 | **5** |
| Playwright E2E specs | 5 | — | покрыты 4 из ~8 доменных потоков |

Ключевой риск: **бизнес-логика денежных и складских операций**
(`wms/transfers/[id]/dispatch|receive|reject`, `wms/stock/[id]/location`,
`wms/inventories/[id]`, `eps/import/execute`, `srm/sync`) не имеет
исполняемых контрактных тестов вообще. Это самые дорогие в откате пути.

## Scope

Данная story — **зонтичная дорожная карта**, а не единица реализации.
Она фиксирует приоритеты, целевые метрики и ratchet-график порогов.
Вся фактическая работа выполняется в дочерних stories O1–O7.

Входит:

- определение приоритетов покрытия по риску, а не по объёму кода;
- фиксация ratchet-графика порогов в [`scripts/check-coverage.mjs`](../../scripts/check-coverage.mjs);
- правила качества тестов (запрет тавтологий и placeholder-ов);
- порядок исполнения и зависимости между O1–O7.

Не входит: изменение бизнес-контрактов, схемы БД, публичных API,
UI-поведения. Тесты фиксируют текущее поведение; найденные дефекты
оформляются отдельными stories, а не «чинятся по ходу».

## Приоритизация по риску

Покрытие набирается в порядке **убывания стоимости отказа**, а не в
порядке удобства:

| Ранг | Класс кода | Почему первым | Story |
|---|---|---|---|
| R1 | Write-роуты с денежным/складским эффектом | необратимые изменения остатков | O2 |
| R2 | AuthN/AuthZ, webhooks, file access, setup | обход RBAC = компрометация | O1 |
| R3 | Доменные сервисы и pure logic | ядро бизнес-правил, дёшево тестировать | O3 |
| R4 | Остальные API-роуты (read/CRUD) | контракт для фронта | O4 |
| R5 | Reusable UI primitives | переиспользуются везде | O5 |
| R6 | Доменные формы и страницы | сложные, но локализованные | O6 |
| R7 | Сквозные E2E-потоки | ловят интеграционные разрывы | O7 |

## Целевые метрики и ratchet

Пороги повышаются **только после** фактического достижения, отдельным
коммитом, и никогда не понижаются (правило ratchet из
[`docs/quality/COVERAGE_BASELINE.md`](../../docs/quality/COVERAGE_BASELINE.md)).

| Этап | Line (loaded) | File reach | Component | Условие перехода |
|---|---:|---:|---:|---|
| Baseline 2026-09-01 | 70 | 22 | 1 | — |
| После O1 | 72 | 30 | 1 | security-роуты зелёные |
| После O2 | 74 | 40 | 1 | write-роуты зелёные |
| После O3 | 78 | 48 | 1 | сервисы и pure logic зелёные |
| После O4 | 80 | 62 | 1 | 85/85 роутов имеют контракт-тест |
| После O5 | 80 | 62 | 12 | UI primitives зелёные |
| После O6 | 80 | 62 | 25 | доменные формы зелёные |
| После O7 | 82 | 65 | 25 | E2E-набор стабилен в CI |

`fileCoverageRatio` — главная метрика этой дорожной карты: она
не поддаётся «накрутке» тестами на уже покрытых файлах.

## Правила качества тестов (обязательны для O1–O7)

1. **Никаких тавтологий.** Тест, который ассертит константу или результат
   собственного мока, отклоняется на ревью (прецедент:
   [`M4`](../done/2026-08/M4-eliminate-tautological-tests.md)).
2. **Никакого статического анализа вместо исполнения.** Проверка
   исходного текста роута регуляркой не является тестом роута
   (прецедент: [`N4`](../done/2026-08/N4-replace-source-text-route-tests.md)).
3. **Каждый write-роут** проверяется минимум по 5 осям: success,
   validation-failure, unauthenticated (401), forbidden (403),
   persistence-failure (500 без утечки внутренней ошибки).
4. **RBAC-негатив обязателен.** Тест с пользователем без нужного
   permission должен получать 403, а не 200.
5. **Rate limit проверяется там, где он объявлен** в
   [`.agents/rules/security.md`](../../.agents/rules/security.md).
6. **Prisma не подключается.** Используется `makePrismaMock()` из
   [`route-harness.ts`](../../apps/web/src/lib/__tests__/helpers/route-harness.ts);
   попытка `$connect()` внутри unit-теста роута — падение теста.
7. **Тест падает при регрессии.** Перед коммитом автор ломает
   production-код и убеждается, что тест краснеет.

## Steps

1. Завести дочерние stories O1–O7 в [`plans/active/`](.) по шаблону
   [`story.md`](../templates/story.md).
2. Исполнять O1 → O7 строго последовательно по рангу риска; параллелизм
   допускается только внутри одной story.
3. После каждой закрытой story: `pnpm test`,
   `node scripts/check-coverage.mjs --report`, `pnpm lint`, typecheck,
   `node scripts/check-doc-links.mjs`.
4. Поднять пороги в [`scripts/check-coverage.mjs`](../../scripts/check-coverage.mjs)
   до значений строки соответствующего этапа и перегенерировать
   [`COVERAGE_BASELINE.md`](../../docs/quality/COVERAGE_BASELINE.md)
   отдельным коммитом `chore: raise coverage ratchet after OX`.
5. Закрыть O0 только после закрытия O1–O7 и достижения целевой строки
   «После O7».
