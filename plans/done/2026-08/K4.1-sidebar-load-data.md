## Bounded sub-story

Вынести из [`Sidebar.tsx`](../../../apps/web/src/components/layout/Sidebar.tsx)
минимально необходимую orchestration-логику загрузки семи endpoint-ответов в
соседний модуль/модули без изменения URL, интервала 20 секунд, порядка запросов,
условий принятия ответов или обновляемых состояний. Сохранить существующее
поведение collapsed flyout, permission gating и навигации.

Рефакторинг ограничен `loadData` и его непосредственными pure response
helpers. Presentation, routing, permissions, endpoint security и unrelated
layout-код не входят в scope.

## Acceptance criteria

1. Реальная complexity `loadData` в [`Sidebar.tsx`](../../../apps/web/src/components/layout/Sidebar.tsx)
   становится `≤ 10`, либо оставшееся значение обосновано в Result.
2. Для каждого из семи response branches добавлены unit-тесты на успешный,
   неуспешный и неподходящий response shape, насколько это применимо к
   вынесенному pure helper API.
3. URL, HTTP methods (default GET), polling interval, state mapping, permission
   gating, collapsed flyout и navigation behavior не изменяются.
4. Проходят targeted tests, lint, TypeScript build/check и quality baseline.
5. Изменения не затрагивают security, UI presentation или другие активные
   истории; stage закрывается отдельным Conventional Commit.

## Ponytail check

Rung 1 не срабатывает: `loadData` обслуживает видимые operational counters и
module availability, требуемые текущим sidebar-контрактом.

Rung 2–4: браузерные fetch/Promise APIs и существующий React state остаются на
месте; новая dependency не нужна.

Rung 6: minimum implementation — извлечь только response mapping/orchestration,
который нужен для снижения реальной ветвистости. Не создавать общий data-fetching
framework; upgrade path — выделять отдельные domain models только если будущие
counter sources начнут повторяться за пределами sidebar.
