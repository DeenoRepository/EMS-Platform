# K4.6 — Декомпозировать сборку системных настроек

## Problem

Повторное измерение после K4.5 показывает, что реальная бизнес-функция
[`getSystemSettings()`](../../../apps/web/src/lib/system-settings-service.ts:29) имеет
`cx 32` и 65 строк по границам quality checker. Функция одновременно проверяет
in-memory cache, читает Prisma records, строит map, применяет env fallback,
собирает основной конфиг и обрабатывает database error fallback.

## Verified map

- [KNOWN] Единственный источник данных функции —
  [`prisma.systemSetting.findMany()`](../../../apps/web/src/lib/system-settings-service.ts:36).
- [KNOWN] Кэш инвалидируется после сохранения настроек через
  [`invalidateSystemSettingsCache()`](../../../apps/web/src/app/api/admin/settings/route.ts:87).
- [KNOWN] Результат используется login route и legacy Jira sync через
  [`getSystemSettings()`](../../../apps/web/src/app/api/auth/login/route.ts:31) и
  [`getSystemSettings()`](../../../apps/web/src/lib/jira/sync.ts:98).
- [KNOWN] Публичный контракт — `Promise<SystemSettingsConfig>`; поля и legacy
  aliases объявлены в [`SystemSettingsConfig`](../../../apps/web/src/lib/system-settings-service.ts:6).
- [KNOWN] В существующем test runner нет теста для system-settings service.
- [KNOWN] Новая dependency не требуется; helper может использовать только
  существующие TypeScript types, `process.env` и plain object operations.

## Scope

Вынести только pure config construction и fallback mapping из
[`getSystemSettings()`](../../../apps/web/src/lib/system-settings-service.ts:29) в
соседний тестируемый модуль. Сохранить cache TTL, Prisma query, env precedence,
default values, provider type, legacy aliases, logger behavior и публичный
`SystemSettingsConfig` contract.

Не менять API routes, authentication, Jira/SRM behavior, Prisma schema, cache
invalidation, environment variable names, UI, K6 или другие K4 candidates.

## Steps

1. Зафиксировать pure builder input/output contract и все consumers.
2. Вынести минимальные pure helpers для database records plus environment fallback.
3. Добавить focused tests для database overrides, env fallback, defaults and
   legacy aliases.
4. Перенаправить service на helper без изменения cache/error orchestration.
5. Повторно измерить complexity и запустить targeted/full test, lint, web tsc и
   quality baseline.

## Ponytail check

Rung 1 не срабатывает: этот service обслуживает динамические настройки для
login и SRM integration flows.

Rungs 2–4: plain object construction и `process.env` уже являются native APIs;
новая dependency или общий configuration framework не нужны.

Rung 6: minimum implementation — один соседний pure builder с узким входным
типом и focused tests. Upgrade path — разделить provider-specific configuration
только если новые consumers потребуют отдельные конфигурационные контракты.
