# K4.4 — Декомпозировать генератор ключа пользовательского поля EPS

## Problem

Повторное измерение quality checker после K4.1–K4.3 показывает реальную
цикломатическую сложность `makeEnglishSlug` равной `cx 14` в
[`eps-import-helpers.ts`](../../apps/web/src/lib/eps-import-helpers.ts:281).
Функция совмещает canonical dictionary lookup, phrase matching, перевод слов,
транслитерацию и fallback-генерацию ключа.

## Verified map

- [KNOWN] Единственная рабочая ссылка на `makeEnglishSlug` находится в
  [`eps-import-matcher.ts`](../../apps/web/src/lib/eps-import-matcher.ts:132),
  где функция используется только для `suggestedKey` неизвестной колонки.
- [KNOWN] Публичный экспорт функции находится в
  [`eps-import-helpers.ts`](../../apps/web/src/lib/eps-import-helpers.ts:281).
- [KNOWN] Канонические ключи и порядок phrase matching определяются
  `CANONICAL_FIELD_DICTIONARY`; поведение должно остаться прежним.
- [KNOWN] Текущего focused unit-теста для `eps-import-helpers.ts` в репозитории
  не найдено; тестовый раннер подхватывает новые `*.test.ts` файлы.
- [KNOWN] Fallback использует существующий `crypto.randomUUID`; новая
  dependency не нужна.

## Scope

Вынести минимальные pure helpers для canonical lookup, token translation и
slug sanitization рядом с текущим владельцем и оставить внешний экспорт
`makeEnglishSlug` без изменения. Сохранить exact canonical match, first-match
phrase semantics, русскую транслитерацию, разделители, очистку slug и случайный
fallback `custom_field_<8 hex>`. Добавить focused unit-тесты для canonical,
phrase, translation/sanitization и fallback branches.

Не менять `CANONICAL_FIELD_DICTIONARY`, `RU_WORD_TRANSLATE`,
`eps-import-matcher.ts`, API import route, Prisma semantics, UI, security,
K6 или другие K4-кандидаты.

## Acceptance criteria

1. Complexity `makeEnglishSlug` становится `≤ 10` либо остаток обоснован в
   Result.
2. Существующее поведение покрыто focused tests для canonical exact/phrase,
   русско-английского перевода, очистки и пустого fallback.
3. `mapFileHeaders` продолжает получать те же `suggestedKey` для тех же входов.
4. Проходят targeted tests, полный test gate, lint, web TypeScript и quality
   baseline.
5. Изменения ограничены этой bounded story и закрываются отдельным
   Conventional Commit.

## Ponytail check

Rung 1 не срабатывает: slug нужен для предложенного ключа новых custom fields
во время EPS import mapping.

Rung 2–4: используются существующие `String`/`Array` APIs, текущие словари и
встроенный `crypto`; новая dependency или общий utility framework не нужны.

Rung 6: minimum implementation — извлечь только pure lookup/translation/
sanitization helpers, необходимые для снижения branch density, без изменения
алгоритма и публичного API.

## Result

Implemented 2026-08-30. Extracted canonical lookup, token translation and slug
sanitization helpers from `makeEnglishSlug` without changing its public API or
any EPS import consumer. Added focused tests for canonical exact/phrase
matching, translation, sanitization and random fallback behavior.

The checker now places `makeEnglishSlug` below the high-complexity threshold;
all bounded acceptance criteria and validation gates passed. The story remains
active until its dedicated Conventional Commit is created and the generated
plans index is synchronized.
