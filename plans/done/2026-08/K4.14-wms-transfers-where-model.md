# K4.14 — Декомпозировать построение фильтра списка перемещений WMS

## Problem

Повторное измерение quality checker после K4.13 подтвердило verified business
candidate [`buildTransferWhereInput()`](../../../apps/web/src/lib/wms-transfers-service.ts:46)
с `cx 26` / 73 строками. Функция совмещает mode/warehouse scoping, status
overrides и search relation filter construction.

Presentation-only boundaries и unrelated K4/K6 work не входят в scope.

## Verified map

- [KNOWN] Единственный consumer — [`GET()`](../../../apps/web/src/app/api/wms/transfers/route.ts:20).
- [KNOWN] Consumer передает `mode`, optional `status`, optional `warehouseId`,
  normalized `search` и current `userId`.
- [KNOWN] Returned value is passed directly to Prisma `stockTransfer.count()` and
  `findMany()` as a `Prisma.StockTransferWhereInput`.
- [KNOWN] Warehouse scoping, mode-specific status behavior and search relations
  must remain unchanged.
- [KNOWN] Existing WMS transfer service and discovered web test location require
  no new dependency or test framework.

## Scope

Extract only the pure mode/warehouse scope and search-filter construction from
`buildTransferWhereInput()`. Keep the public function name and Prisma where
contract unchanged. Add focused tests for mode/status/warehouse and search
composition.

Do not change API URL/method, auth, rate limiting, permissions, Prisma semantics,
POST behavior, UI, K6, or other K4 candidates.
