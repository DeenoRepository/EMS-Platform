# K4.1.1 — Вынести применение operational counters в Sidebar

## Problem

После K4.1 endpoint orchestration вынесена из `Sidebar.tsx`, но локальная
`loadData` всё ещё содержит повторяющиеся conditional state updates и имеет
остаточную реальную complexity `cx 13`.

## Scope

- Вынести только применение `SidebarDataUpdate` к существующим React setters.
- Сохранить условия `!== undefined`, значения `null`/`0`, polling interval,
  endpoint order, navigation, permissions и collapsed flyout behavior.
- Не менять API, response mapping, security или presentation.

## Steps

1. Зафиксировать существующие state fields и setter mapping чтением `Sidebar.tsx`.
2. Вынести минимальный pure orchestration helper с callback-based setters.
3. Добавить unit-тесты на partial update, null/zero и отсутствие обновления
   отсутствующих полей.
4. Запустить targeted tests, полный test, lint, web tsc и quality baseline.

## Definition of Done

- [x] Реальная complexity `loadData` в `Sidebar.tsx` становится `<= 10`.
- [x] Все state mapping semantics покрыты unit-тестами.
- [x] UI/polling/navigation/permission behavior не изменён.
- [x] Full gates green: test, lint, tsc, quality.

## Result

Implemented and committed as [`9516917`](../../../plans/README.md).

- Extracted conditional application of all sidebar operational counter state into
  `applySidebarDataUpdate()` and kept the polling/effect owner in `Sidebar.tsx`.
- Added coverage for partial updates, `null`, and zero values.
- Web TypeScript check, targeted tests, lint, and quality baseline passed.

  React hook dependency warning; the repository is clean after removing the
