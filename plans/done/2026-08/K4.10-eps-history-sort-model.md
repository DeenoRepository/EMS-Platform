# K4.10 — Декомпозировать сортировку истории аудита EPS

## Problem

Повторное измерение после закрытия K4.9 показывает следующий проверенный business
candidate — inline [`sortedItems`](../../../apps/web/src/app/eps/history/page.tsx:144)
с `cx 40` и 120 строками по границам quality checker. Он содержит реальную
табличную сортировку истории аудита по дате, пользователю, действию, сущности и
оборудованию. Численно более высокие результаты для
[`WmsOperationWizardDialog`](../../../apps/web/src/components/wms/WmsOperationWizardDialog.tsx:1),
[`parseDateSafe()`](../../../apps/web/src/app/api/eps/equipment/[id]/route.ts:148) и
SRM/presentation boundaries не входят в эту bounded stage.

## Scope

Extract only the pure EPS audit-history item sorting model currently implemented
inside `sortedItems`. Preserve field precedence, date fallback, locale (`ru`),
ascending/descending behavior, unknown-field fallback, and non-mutating input
semantics. Do not change API routes, query behavior, permissions, pagination,
rendering, or K6/unrelated K4 candidates.

One logical remediation stage: EPS audit-history client-side sorting model.

## Steps

1. Add a neighboring pure sorting helper with the existing `AuditLogItem` shape.
2. Replace only the inline `sortedItems` comparator with the helper.
3. Add focused tests for every supported sort field, direction, fallback, invalid
   date fallback, and input immutability.
4. Re-measure the candidate and run targeted/full tests, lint, web tsc, quality,
   and docs/plans checks.
5. Close and move this story to `plans/done/2026-08/` after the successful
   implementation commit.
