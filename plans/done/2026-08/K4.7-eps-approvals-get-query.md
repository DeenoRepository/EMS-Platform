# K4.7 — Декомпозировать GET списка согласований EPS

## Problem

Повторное измерение после K4.6 показывает, что реальная бизнес-функция
[`GET()`](../../../apps/web/src/app/api/eps/approvals/route.ts:12) имеет `cx 29` и
159 строк по границам quality checker. Она одновременно проверяет разрешения,
разбирает query-параметры, строит Prisma-фильтр, загружает список и агрегаты,
строит scoped statistics и формирует response.

При измерении дополнительно подтверждено, что более высокие результаты для
[`WmsOperationWizardDialog`](../../../apps/web/src/components/wms/WmsOperationWizardDialog.tsx),
[`parseDateSafe()`](../../../apps/web/src/app/api/eps/equipment/[id]/route.ts:148),
[`handleRequestSort()`](../../../apps/web/src/app/eps/history/page.tsx:84) Рё
SRM render boundaries являются checker boundary/presentation false positives,
а не отдельными бизнес-функциями для следующего bounded stage.

## Verified map

- [KNOWN] Единственный consumer route handler —
  [`apps/web/src/app/api/eps/approvals/route.ts`](../../../apps/web/src/app/api/eps/approvals/route.ts).
- [KNOWN] Handler вызывается UI через существующие approvals page fetch flow;
  публичный response shape содержит `success` и `data.items`, `total`, paging и
  `stats`, поэтому route contract должен сохраниться.
- [KNOWN] Prisma models и enums используются из `@ems/database` через
  `Prisma.EquipmentApprovalWhereInput`, `ApprovalStatus` Рё `ApprovalType`.
- [KNOWN] Authorization, rate limiting, `safeErrorResponse`, query semantics,
  pagination and statistics are currently owned by the handler and must remain
  unchanged externally.
- [KNOWN] Existing test runner discovers `apps/web/src/lib/__tests__` and
  package tests; no focused approvals route test was found during inspection.
- [KNOWN] No new dependency is required; pure query parsing/filter/stat helpers
  can use existing TypeScript types and plain objects.

## Scope

Вынести только pure query/filter/stat construction из
[`GET()`](../../../apps/web/src/app/api/eps/approvals/route.ts:12) в соседний
тестируемый модуль, затем перенаправить handler на helpers. Покрыть focused
тестами status/type/scope/search filters и scoped statistics.

Сохранить без изменений rate limiting, auth/RBAC, Prisma query shape and
includes, pagination, response JSON contract, permission semantics, API route,
POST handler, UI, K6 and other K4 candidates.

Один logical remediation stage: только GET approvals query/stat orchestration;
не извлекать POST helpers и не менять database behavior.

## Steps

1. Зафиксировать pure input/output contracts на основе текущего handler.
2. Вынести минимальные query parsing/filter и statistics helpers рядом с route.
3. Добавить focused tests для mode/status/type/search filters and statistics.
4. Перенаправить только GET handler на helpers.
5. Повторно измерить complexity и выполнить targeted/full tests, lint, web tsc,
   quality baseline Рё docs link checks.
