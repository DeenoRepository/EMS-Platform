# Дорожная карта компонентов новой архитектуры EMS Platform

Данный документ содержит пошаговый технический план создания и миграции каждого отдельного репозитория системы.

---

## 1. Репозиторий `@platform/contracts`

Контрактный репозиторий является единственной общей зависимостью между ядром, расширениями и бизнес-модулями.

### Этапы реализации:
1. **Базовые типы платформы:**
   * Определение контекста пользователя: `IUserContext`, `IRole`, `IPermission`.
   * Системные коды ошибок и стандартный конверт HTTP API `ApiResponse<T>`.
2. **Контракты шины сообщений (`EventBus`):**
   * Интерфейс [`IEventBus`](packages/shared/src/types.ts:1) (`publish`, `subscribe`, `unsubscribe`).
   * Zod-схемы валидации заголовков событий (`DomainEventEnvelope`).
3. **Контракты точек расширения ядра (SPI):**
   * `IAuthProvider` — методы `authenticate(credentials)`, `validateSession(token)`.
   * `IStorageProvider` — методы `upload(file)`, `download(key)`, `delete(key)`.
   * `IAuditLogger` — метод `logAuditEvent(event)`.
4. **Реестр типов бизнес-событий платформы:**
   * События EPS: `eps.equipment.created`, `eps.equipment.updated`, `eps.equipment.decommissioned`.
   * События WMS: `wms.stock.reserved`, `wms.stock.issued`, `wms.stock.depleted`.
   * События MRO: `mro.work_order.created`, `mro.spare_parts.requested`, `mro.maintenance.completed`.
   * События PRM: `prm.demand.created`, `prm.order.approved`, `prm.order.received`.
5. **Тестирование (TDD):**
   * Юнит-тесты валидации всех Zod-схем на корректные и некорректные payload.

## 2. Репозиторий `platform-shell` (Ядро системы)

Ядро компилируется как легковесный хост-сервер (Node.js/Fastify/Next.js) без предметной логики.

### Этапы реализации:
1. **Ядро безопасности и авторизации (Core Security):**
   * Таблицы схемы `core`: `users`, `roles`, `role_permissions`, `sessions`.
   * Middleware проверки прав доступа (RBAC Guard) по заголовкам/сессиям.
2. **Менеджер модулей и расширений (Lifecycle Engine):**
   * Сканирование каталога установленных пакетов или манифестов `module.manifest.json`.
   * Динамическая загрузка классов инициализации `IModuleBootstrap` и регистрация роутов.
   * Регистрация навигационных пунктов для левого меню UI Shell.
3. **Шина событий (In-Process Event Bus):**
   * Асинхронная доставка событий подписчикам внутри процесса.
   * Перехват необработанных исключений подписчиков без падения сервера.
   * Обработка Transactional Outbox (фоновый процесс поллинга outbox-таблиц).
4. **UI App Shell (Frontend):**
   * Контейнер приложения: верхняя панель (профиль пользователя, уведомления), боковое меню (динамически наполняемое из манифестов модулей).
   * Единая дизайн-система и палитра темы оформления.
   * Динамическое монтирование страниц модулей.

## 3. Репозитории расширений ядра (`ext-*`)

Каждое расширение подключается через SPI ядра и настраивается через переменные окружения/конфигурационный файл.

### 3.1. `ext-auth-ldap`
* Реализует интерфейс `IAuthProvider`.
* Вынос текущей логики из [`packages/auth/src/ldap.ts`](packages/auth/src/ldap.ts).
* Подключение к корпоративному каталогу Active Directory/LDAP, поиск групп и маппинг в роли EMS Platform.
* TDD: Тестирование санитизации поисковых фильтров (`escapeLdapFilter`) и маппинга ролей.

### 3.2. `ext-storage-s3`
* Реализует интерфейс `IStorageProvider`.
* Хранение файлов паспортов, сертификатов, чертежей и актов в S3-совместимом хранилище (MinIO/Ceph/AWS).
* TDD: Тестирование генерации presigned URL и валидации MIME-типов.

### 3.3. `ext-audit-syslog`
* Реализует интерфейс `IAuditLogger`.
* Вынос текущей логики из [`packages/auth/src/audit.ts`](packages/auth/src/audit.ts).
* Асинхронная отправка структурированных логов событий безопасности по протоколу RFC 5424 (Syslog UDP/TCP).

## 4. Репозитории бизнес-модулей (`module-*`)

### 4.1. `module-eps` (Electronic Passport System)
* **Назначение:** Полный учет парка технологического оборудования предприятия.
* **Схема БД:** `eps` (`eps_equipment`, `eps_specifications`, `eps_documents`, `eps_nodes`).
* **Ключевые сервисы:**
  * Сервис генерации инвентарных номеров и QR-кодов.
  * Сервис расчета амортизации и нормативного ресурса.
  * Валидатор технических паспортов.
* **Интеграция с шиной:**
  * Публикует `eps.equipment.created`, `eps.equipment.updated`, `eps.equipment.decommissioned`.
* **TDD-сценарии:** Проверка расчета нормативного износа, генератор уникальных номеров, валидация полей паспорта.

### 4.2. `module-wms` (Warehouse Management System)
* **Назначение:** Управление складскими запасами, адресное хранение, материальные движения.
* **Схема БД:** `wms` (`wms_stock_items`, `wms_warehouses`, `wms_cells`, `wms_movements`, `wms_batches`).
* **Ключевые сервисы:**
  * Алгоритм списания партий (FIFO / LIFO).
  * Сервис резервирования складских позиций по нарядам.
  * Процессинг актов инвентаризации и учет расхождений.
* **Интеграция с шиной:**
  * Слушает: `prm.order.received` (автоматический приход ТМЦ на карантинный склад).
  * Слушает: `mro.spare_parts.requested` (резервирование запчастей под наряд ТОиР).
  * Публикует: `wms.stock.reserved`, `wms.stock.issued`, `wms.stock.depleted`.
* **TDD-сценарии:** Изолированные расчеты партий FIFO, предотвращение отрицательных остатков, транзакционное резервирование.

### 4.3. `module-mro` (Maintenance, Repair, Overhaul)
* **Назначение:** Планирование и контроль выполнения технического обслуживания и ремонтов.
* **Схема БД:** `mro` (`mro_schedules`, `mro_work_orders`, `mro_checklists`, `mro_incidents`).
* **Ключевые сервисы:**
  * Планировщик периодических ТО по календарю и наработке часов.
  * Валидатор допуска исполнителей и чек-листов перед закрытием наряда.
  * Калькулятор простоев технологических линий.
* **Интеграция с шиной:**
  * Слушает: `eps.equipment.decommissioned` (автоматическая отмена запланированных ТО).
  * Публикует: `mro.spare_parts.requested` (запрос запчастей со склада).
  * Публикует: `mro.maintenance.completed` (обновление наработки и статуса оборудования).
* **TDD-сценарии:** Расчет дат следующего ТО с учетом сменности, проверка полноты выполнения чек-листа.

### 4.4. `module-prm` (Procurement & Requests)
* **Назначение:** Сбор потребностей подразделений, согласование заявок на закупку, контроль цепочки поставок.
* **Схема БД:** `prm` (`prm_requests`, `prm_demands`, `prm_orders`, `prm_approval_steps`).
* **Ключевые сервисы:**
  * Механизм матричного согласования (по суммам и подразделениям).
  * Агрегатор однотипных складских дефицитов в сводный лот закупки.
  * Контроллер статусов поставки.
* **Интеграция с шиной:**
  * Слушает: `wms.stock.depleted` (автоматическое формирование проекта потребности).
  * Публикует: `prm.order.received` (уведомление склада о прибытии ТМЦ).
* **TDD-сценарии:** Матрица прав утверждения заявок, агрегация позиций ТМЦ, валидатор лимитов бюджетов.

## 5. Репозиторий сборки и деплоя `platform-distribution`

### Компоненты:
1. **Сборочный процесс:**
   * Базовый Docker-образ ядра `ems-shell:latest`.
   * Установка и сборка активных плагинов в единый runtime-контейнер через npm-зависимости или git-пакеты.
2. **Конфигурация инфраструктуры (`docker-compose.prod.yml`):**
   * Контейнер приложения (Shell + подключенные модули).
   * База данных PostgreSQL 16 с предустановленными правами и схемами (`core`, `eps`, `wms`, `mro`, `prm`).
   * Кэш/брокер Redis (опционально для кэширования сессий и брокера шины).
   * Nginx Reverse Proxy (SSL-терминация, сжатие, раздача статики).
3. **Мигратор базы данных:**
   * Утилита последовательного применения миграций для каждой изолированной схемы при старте контейнера.
4. **Мониторинг:**
   * Healthcheck эндпоинты `/health/live` и `/health/ready` (проверка соединения с БД и состояния шины).
