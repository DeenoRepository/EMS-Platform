# Каталог скиллов для агентной разработки EMS Platform

Данный каталог формируется на базе библиотеки [alirezarezvani/claude-skills](https://github.com/alirezarezvani/claude-skills) и развертывается в приватном репозитории управления `platform-governance/.skills/`.

---

## 1. Реестр обязательных скиллов

| Скилл | Направление | Ключевые функции | Когда активируется агентом |
|---|---|---|---|
| **`senior-architect`** | Архитектура и дизайн | Проектирование модульных контрактов, выбор паттернов, проверка связности компонентов, составление ADR. | При проектировании новых модулей, расширений ядра или изменении протоколов шины сообщений. |
| **`zero-hallucination-coder`** | Разработка логики | Цикл *Discuss -> Map -> Decompose -> Execute -> Verify*. Запрет на использование вымышленных API и непроверенных зависимостей. | Основной скилл при реализации доменных сервисов и модулей. |
| **`strict-api`** | Интеграции и контракты | Верификация сигнатур методов и импортов строго по установленным типам `@platform/contracts`. | При подключении модулей к шине событий и вызовах SPI-расширений. |
| **`database-schema-designer`** | Базы данных | Проектирование нормализованных таблиц, схем PostgreSQL (`eps.*`, `wms.*`), миграций без перекрестных внешних ключей. | При создании схем модулей и оптимизации индексов. |
| **`senior-backend`** | Серверная инженерия | Разработка контроллеров, валидация входных данных (Zod), транзакционные границы, оптимизация запросов. | При реализации API-слоя ядра и бизнес-модулей. |
| **`senior-qa`** | TDD и тестирование | Построение изолированных юнит-тестов, генерация тестовых фикстур, mock-провайдеры для шины сообщений. | На первом этапе каждой задачи (написание падающих тестов в TDD). |
| **`code-reviewer`** | Аудит качества | Анализ цикломатической сложности, SOLID-принципов, проверка отсутствия AI-артефактов в коммитах. | Финальный шаг перед выполнением `git commit`. |
| **`senior-security` / `senior-secops`** | Безопасность | Моделирование угроз (STRIDE), аудит RBAC-гардов, предотвращение инъекций, санитизация входных данных. | При разработке роутов авторизации, вебхуков и публичных API. |
| **`docker-development`** | Контейнеризация | Написание multi-stage Dockerfile для Shell и модулей, оптимизация слоев, подготовка docker-compose. | При конфигурировании окружения и сборке дистрибутива. |
| **`ci-cd-pipeline-builder`** | Автоматизация CI/CD | Создание пайплайнов GitHub Actions / GitLab CI для прогона TDD-тестов, сборки образов и проверки линтерами. | При инициализации новых репозиториев модулей. |

## 2. Матрица применения скиллов по жизненному циклу задачи

Каждая задача, выполняемая агентом в рамках любого продуктового репозитория, проходит через следующую цепочку активации скиллов:

```
[1. Анализ и Спецификация]
   ↳ `senior-architect` + `strict-api`
   (Анализ контрактов шины, DTO, формирование плана изменений)
               │
               ▼
[2. Проектирование Данных (при наличии изменений в схеме)]
   ↳ `database-schema-designer`
   (Миграции изолированной схемы модуля, индексы, outbox-таблица)
               │
               ▼
[3. TDD-разработка Бизнес-Логики]
   ↳ `senior-qa` + `zero-hallucination-coder` + `senior-backend`
   (Шаг 1: Написание падающего теста -> Шаг 2: Реализация кода -> Шаг 3: Проверка типов)
               │
               ▼
[4. Аудит Безопасности и Качества]
   ↳ `senior-security` + `code-reviewer`
   (Проверка RBAC, валидация отсутствия маркеров ИИ, проверка чистоты Git diff)
               │
               ▼
[5. Фиксация и Автоматизация]
   ↳ `ci-cd-pipeline-builder` + `docker-development`
   (Git commit, проверка успешного прохождения локального CI)
```

---

## 3. Процедура установки и синхронизации скиллов

1. **Размещение в репозитории управления:**
   * В репозитории `platform-governance` создается каталог `.skills/`.
   * Каждый скилл клонируется или импортируется из официального репозитория `https://github.com/alirezarezvani/claude-skills`.
2. **Изоляция от продуктовых репозиториев:**
   * Продуктовые репозитории модулей и ядра не содержат подмодулей или символических ссылок на каталог скиллов.
   * Агент при запуске сессии обращается к локальной директории или клону `platform-governance` как к источнику правил среды.
