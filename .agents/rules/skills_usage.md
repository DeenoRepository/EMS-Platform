# Правила использования специализированных скиллов и процесса разработки в EMS-Platform

## 🚨 Обязательное правило: Фиксация изменений (Git Commit)
* **После успешного завершения любой задачи, фичи, фикса или логического этапа агент ОБЯЗАН создать Git-коммит.**
* Коммиты должны быть атомарными, содержать понятный заголовок по стандарту Conventional Commits:
  - `feat: <описание>` — добавление нового функционала
  - `fix: <описание>` — исправление ошибок
  - `refactor: <описание>` — оптимизация структуры без изменения поведения
  - `test: <описание>` — добавление тестов
  - `docs: <описание>` — обновление документации
  - `chore: <описание>` — правка конфигураций, зависимостей, скиллов

---

## Использование специализированных скиллов (`.agents/skills/*`)

При выполнении задач в данном репозитории агент ОБЯЗАН обращаться к соответствующим локальным скиллам, изучать их `SKILL.md`, руководства в `references/` и использовать скрипты автоматизации в `scripts/`:

### 1. Фронтенд и компоненты интерфейса (Next.js, React, Material UI)
* **`senior-frontend`**: Использовать при создании/редактировании страниц в `apps/web/src/app`, компонентов `apps/web/src/components`, управлении состоянием и оптимизации рендеринга больших таблиц (DataGrid/MUI) и графиков.
* **`a11y-audit`**: Использовать при разработке и аудите сложных форм (паспорта оборудования, складские накладные, карточки ТО), проверяя доступность и корректность разметки.

### 2. Бэкенд, API, PostgreSQL и Prisma ORM
* **`senior-backend`**: Использовать при создании эндпоинтов `apps/web/src/app/api`, проектировании серверной логики, транзакций и оптимизации запросов к БД.
* **`strict-api`**: Применять для строгой валидации входных/выходных DTO, обработки ошибок и защиты контрактов API.
* **`database-schema-designer`**: Использовать при расширении схемы `packages/database/prisma/schema.prisma` и планировании миграций.

### 3. Авторизация, безопасность и аудит
* **`senior-security` & `senior-secops`**: Использовать при работе с `packages/auth`, механизмами LDAP-аутентификации, JWT-токенами, RBAC-правами (`PERMISSIONS`), а также проверке неизменяемости журнала аудита (`AuditLog`).

### 4. Тестирование и обеспечение качества (QA & E2E)
* **`senior-qa`**: Использовать для генерации модульных и интеграционных тестов с Jest и React Testing Library.
* **`playwright-pro`**: Использовать для написания и прогона E2E-тестов пользовательских сценариев (жизненный цикл оборудования, согласования, инвентаризация) с архитектурой Page Object Model.

### 5. Архитектура и надежность
* **`senior-architect`**: Использовать при добавлении новых пакетов в монорепозиторий, проектировании связей между модулями и обновлении архитектурных документов (ADR).
* **`zero-hallucination-coder`**: Обязательно следовать принципу точного соответствия кодовой базе, существующим TypeScript-типам и ТЗ без выдумывания невалидных интерфейсов.
* **`code-reviewer`**: Использовать для предварительного самоанализа написанного кода, выявления антипаттернов и контроля качества.

### 6. Инфраструктура и интеграции
* **`docker-development`**: Использовать при обновлении Dockerfile, docker-compose.yml и конфигурации окружения.
* **`ci-cd-pipeline-builder`**: Использовать для настройки и поддержки CI/CD пайплайнов.
* **`jira-expert`**: Использовать при доработке модуля SRM, REST API интеграции с Jira и кэширования тикетов.
* **`handoff` & `self-improving-agent`**: Использовать для фиксации состояния контекста задач и сохранения проектных соглашений.
