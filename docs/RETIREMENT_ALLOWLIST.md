# Allowlist оставшихся упоминаний прототипов SRM и MRO

В соответствии с планом передачи [`docs/SRM_MRO_RETIREMENT_MODULARIZATION_PLAN.md`](docs/SRM_MRO_RETIREMENT_MODULARIZATION_PLAN.md) и ADR [`docs/ADR_MODULARIZATION_AND_RETIREMENT.md`](docs/ADR_MODULARIZATION_AND_RETIREMENT.md), активные сервисы, UI-формы, фоновые опросы и мутирующие API прототипов SRM/MRO выведены из эксплуатации.

В настоящем документе зафиксирован исчерпывающий перечень разрешенных временных упоминаний, обоснование их сохранения, владелец и условие последующего вывода.

---

## 1. Модели физической схемы базы данных (Prisma Schema)

| Модель / Таблица | Причина сохранения | Владелец | Условие последующего удаления |
|---|---|---|---|
| `model MaintenancePlan` | Обеспечение обратной совместимости схемы PostgreSQL первого релиза; сохранность исторических планов оборудования | Database Infrastructure | Отдельный этап миграции данных после согласования с заказчиком |
| `model MaintenanceSchedule` | Сохранность истории ранее зафиксированных фактов проведения регламентных работ | Database Infrastructure | Согласованный перенос в долгосрочный архив или удаление после истечения срока хранения |
| `model ChecklistTemplate` | Хранение структуры исторических регламентных карт ТО | Database Infrastructure | Вывод после архивации |
| `model ChecklistItemTemplate` | Пункты исторических чек-листов | Database Infrastructure | Вывод после архивации |
| `model ChecklistExecutionItem` | Фактические отметки пунктов выполнения старых ТО | Database Infrastructure | Вывод после архивации |
| `model SrmIssue` | Сохранность журнала исторических инцидентов | Database Infrastructure | Вывод после архивации |
| `model SrmIntegration` | Хранение конфигурации старых подключений (в отключенном состоянии) | Database Infrastructure | Вывод в DDL-релизе схемы |
| `model SrmWebhookLog` | История аудита входящих запросов | Database Infrastructure | Ротация по TTL или очистка в миграционном релизе |
| `model JiraIssueCache` | Кеш ранее загруженных инцидентов для отображения в паспорте оборудования | Database Infrastructure | Вывод после согласования схемы |

## 2. Слой архивного чтения (Read-Only History)

| Компонент / Код | Назначение | Ограничение |
|---|---|---|
| `apps/web/src/app/eps/[id]/page.tsx` (вкладки 4 и 5) | Просмотр истории ранее проведенных ТО и зарегистрированных обращений | **Строго Read-Only**: кнопки создания, редактирования, списания ЗИП и внешняя синхронизация удалены |
| `apps/web/src/app/api/eps/equipment/[id]/route.ts` | Выборка `maintenancePlans` и `jiraIssueCache` | Прямое чтение из БД без сетевых вызовов и без фоновой синхронизации |
| `apps/web/src/app/api/eps/reports/generate/route.ts` | Включение исторических счетчиков ТО/инцидентов в отчеты оборудования | Честное историческое значение без генерации ложных нулей |

## 3. Декоммиссионированные конечные точки (Safe Retired Adapters)

| Маршрут | Поведение | Обоснование |
|---|---|---|
| `POST /api/srm/webhooks/[id]` | Возвращает 200 OK `{ success: true, status: "retired" }` | Предотвращение бесконечных повторных запросов (retry loop) от ранее настроенных внешних систем |
| `/srm`, `/mro` | Отображают информационный баннер `ModuleMaintenanceState` о выводе из эксплуатации | Предсказуемая обработка старых ссылок из уведомлений и закладок пользователей без 500 ошибок |

---

## 4. Каталог прав и ролей (RBAC)

| Права | Поведение | Обоснование |
|---|---|---|
| `srm.*`, `mro.*` | Сохранены в `PERMISSIONS` (`@ems/shared`) и в таблице `permissions` | Сохранение целостности существующих ролей пользователей в БД без падения JWT/login |
| Интерфейс `/admin/roles` | Показывает категории как "(Архив)" | Администратор видит существующие права, но создание новых связок с прототипами не поощряется |
