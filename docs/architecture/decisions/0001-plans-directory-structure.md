# ADR-0001: One-file-per-story work ledger under plans/, generated indexes

**Status:** Accepted
**Date:** 2026-08-30

## Context

Work tracking lived entirely in
[`docs/REMEDIATION_PLAN.md`](../../REMEDIATION_PLAN.md), a single file that
grew to 956 lines mixing three different lifecycles: ~38 closed stories
(immutable history), ~8 open stories (actively edited), and a handful of
conditional/backlog items. Symptoms observed during the 2026-08-30
inspection:

- Any status update touched a 956-line file; diffs were unreadable and
  merge conflicts likely for concurrent agents.
- Quality metrics (average score, F-grade count, code smells, SOLID
  violations) were copy-pasted into this file, into
  `.agents/rules/code_quality.md`, into `docs/PROJECT_INSPECTION.md`, and
  into `AGENTS.md` — five independent copies. Three of the five had already
  drifted (81.1 vs 81.7, F=33 vs F=27) by the time this was noticed.
- Closed-story detail (C7–C17) existed only as single-row summaries; the
  "current work" section (phase I) was buried at line 761 of the file.
- No machine-checkable way to detect that a status table was stale.

## Decision

1. Split work tracking into `plans/` at the repository root (not under
   `docs/`, since it is operational state, not reference documentation):
   - `plans/active/<id>-<slug>.md` — one file per open story.
   - `plans/done/YYYY-MM/<id>-<slug>.md` — one file per closed story,
     never edited again after close.
   - `plans/BACKLOG.md` — conditional/unscheduled items, not story files.
   - `plans/templates/story.md` — the schema, enforced via YAML front-matter
     (`id, title, status, phase, priority, risk, skills, opened, closed,
     commits, gates`).
2. `plans/README.md` is **generated**, never hand-edited, by
   [`scripts/plans-index.mjs`](../../../scripts/plans-index.mjs), which
   also validates front-matter and rejects structural mistakes (e.g.
   `status: done` inside `active/`, a `done` story missing `closed:` or
   commits).
3. Quality metrics get the same treatment:
   [`docs/quality/QUALITY_BASELINE.md`](../../quality/QUALITY_BASELINE.md)
   is generated by `scripts/check-quality-baseline.mjs --report` and is the
   only place current metric values may appear. Point-in-time inspection
   reports move to `docs/quality/inspections/<date>-*.md` and are treated as
   immutable snapshots, never updated after the fact.
4. Enforce via CI ([`.github/workflows/ci.yml`](../../../.github/workflows/ci.yml)):
   `plans-index.mjs --check` and a `git diff --exit-code` on the regenerated
   quality baseline. A stale generated file fails the build.
5. Rule of thumb encoded in [`docs/README.md`](../../README.md) and
   [`.agents/rules/skills_usage.md`](../../../.agents/rules/skills_usage.md):
   **no markdown file may hardcode a number or status that a script
   computes or that already lives in exactly one other file.**

## Consequences

**Easier:**
- A story update is a small, reviewable diff in one file.
- Closing a story is a `git mv` plus front-matter edit, not a manual table
  edit in a shared file.
- Drift between "what the rules say" and "what is actually true" becomes a
  CI failure instead of a silent inconsistency.
- Concurrent agents working on different stories no longer collide on the
  same file.

**Harder / trade-offs accepted:**
- More files to navigate (46 files replacing 1) — mitigated by the
  generated index and [`docs/README.md`](../../README.md) navigation table.
- The YAML front-matter parser in `plans-index.mjs` is intentionally
  minimal (flat key/value + single-line flow arrays only) rather than a
  full YAML parser, to avoid a new dependency — this constrains what schema
  extensions are cheap to add later.
- Historical stories migrated from the original plan file were transcribed
  as faithfully as the source allowed; some (`plans/done/2026-08/C7`–`C17`)
  only ever existed as single-row summaries in the source and remain thin
  records rather than full narratives — this is a property of the source
  material, not something this migration could improve without inventing
  detail that was never recorded.
